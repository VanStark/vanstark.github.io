Privacy Policy

Application: m4-offsite-backup  ·  Last updated: 2026-11-25

1. Scope

This policy covers the application m4-offsite-backup, a personal command-line backup client that the operator runs on their own computer. The application has exactly one user: its operator. It is not published, distributed, or made available to any other person, and it has no server-side component.

2. What Google user data the application accesses

The application requests one OAuth scope: https://www.googleapis.com/auth/drive.file. Google defines this scope as per-file access limited to files the application creates or that the user opens with the application. Consequently the application can only see and act on:

  • the single folder it creates in the user's Drive, and
  • the backup archive files and checksum files it uploads into that folder.

The application has no access to any other file in the Google account, and no access to Gmail, Calendar, Contacts, Photos, or account metadata.

3. How the data is used

The data is used for one purpose only: maintaining an offsite copy of the operator's own encrypted backups. Concretely:

  • uploading encrypted archive files and their SHA-256 checksum files into the application's own Drive folder;
  • listing that folder in order to apply a retention rule that keeps only the most recent archives;
  • permanently deleting the application's own superseded archives from that folder (they are not moved to the Drive trash);
  • downloading one of the application's own archives back to local storage to verify its checksum.

No other processing takes place. The application performs no analytics, profiling, indexing, or content inspection.

4. Storage, encryption and retention

Archives are encrypted locally by the operator before upload, using age for archive files and AES-256 for disk images. Google therefore stores ciphertext; the encryption keys are held by the operator and are never sent to Google or to any third party. Retention in the Drive folder is limited to the most recent archives produced by the application; older ones are deleted by the application itself. Local copies remain under the operator's control.

5. Sharing and third parties

The application does not share, sell, transfer, or disclose Google user data to any third party. It does not use Google user data for advertising, for training machine-learning models, or for any purpose unrelated to the backup function described above. There is no intermediary service: the application talks directly to the Google Drive API from the operator's computer.

6. Limited Use

The application's use of Google user data adheres to the Google API Services User Data Policy, including its Limited Use requirements. Data obtained through the Drive API is used only to provide the user-facing backup function described above, is not transferred to others except as necessary to provide that function, and is not used for advertising.

7. Revocation and deletion

The operator can revoke the application's access at any time at myaccount.google.com/permissions. After revocation the application can no longer access any file. Data already stored in Drive can be deleted by the operator directly in Google Drive, or by letting the application's retention rule remove it, and the local archives and keys can be deleted from the operator's own storage at any time. No copy of the data exists anywhere else.

8. Changes

If the application's data practices change, this page will be updated before the change takes effect.
